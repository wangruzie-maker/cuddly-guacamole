# 市场能力工作台 — 产品设计（基于 Product Manager Skills）

> 框架来源：[deanpeters/Product-Manager-Skills](https://github.com/deanpeters/Product-Manager-Skills)  
> 组合使用：`opportunity-solution-tree` + `prd-development` + `roadmap-planning`（Now/Next/Later）  
> 产品定位：独立能力按需使用，必要时组合成调研 → 追踪 → 复盘链路  
> 当前基线：xhs-note-extractor v1.15（小红书/视频号统一工作台）

---

## 1. Desired Outcome（目标结果）

**主结果：** 市场同学可直接调用采集、提取、分析或追踪能力完成各自任务；需要完整决策与复盘时，再按工作流组合这些能力。

### 产品原则

1. **能力优先**：不强制先建项目或填写完整上下文。
2. **单点可用**：每个模块独立产生可带走的结果。
3. **组合可选**：数据可以一键流向下一能力，但不强制。
4. **复杂度后置**：项目、账号、目标和归因仅在复盘需要时启用。

**可量化目标（建议 KPI）：**

| 指标 | 当前粗估 | 目标（90 天） |
|------|----------|---------------|
| 一次选题调研到可用选题包 | 半日～1 日（人工搜+整理） | ≤ 30 分钟 |
| 发布后效果复盘启动成本 | 需另开表格手工记 | 注册链接后自动出趋势 |
| 语料可复用率 | 分散在聊天/网盘 | ≥ 70% 选题包可直接交给生产 |

## 2. Opportunity Solution Tree（机会树）

```text
                    市场部能更高效、可复用地做内容决策与生产输入
                                        |
          +--------------------+--------+--------+--------------------+
          |                    |                 |                    |
     O1 选题难决策        O2 追踪断裂        O3 复盘无体系        O4 语料难沉淀
   （不知道写什么）     （发完没人看数据）    （无法归因好坏）     （爆款正文难取用）
          |                    |                 |                    |
    多维挖掘/模板包       发布回调+趋势图      跨选题对标+归因     一键提取+语料库
    选题包导出 MD         按账号/选题筛选      周报式复盘页        搜索框词/正文切片
```

### 对应机会说明（问题，不是功能）

1. **O1 选题难决策**：同事面对平台热点，缺少可复用的多维分析（场景/对比/联动等），只能凭感觉。
2. **O2 追踪断裂**：发布后成绩分散在 App 里，工具侧登记弱、趋势图易丢、和选题不关联。
3. **O3 复盘无体系**：缺少「选题 × 账号 × 内容类型 × 表现」的统一复盘视图。
4. **O4 语料难沉淀**：即便搜到爆款，正文/标题/标签/搜索联想词难以结构化入库与二次创作。

| 角色 | Jobs-to-be-done | 痛点 |
|------|-----------------|------|
| 市场传播 | 每周稳定产出可发布选题与参考爆款 | 搜完散落、无法横向对比 |

| 增长/负责人 | 看团队选题覆盖与内容 ROI | 只有零散截图与表格 |

## 4. Solution Overview（完整工具形态）

### 4.1 信息架构（目标态）

```text
市场能力工作台
├── 获取选题与依据 关键词/模板 · 深度与阈值 · 数据筛选 · 勾选样本
├── 转录与选题分析 批量 OCR/ASR · 高频主题 · 共现 · 创作选题
├── 数据追踪       语料资产概览 · 自有内容登记 · 指标趋势图
├── 目标复盘（可选）目标进度 · 选题归因 · TOP 语料命中
└── 平台能力       作为采集/手动补充时的选项，不再拆成一级 Tab
```

### 4.2 可选组合路径

1. **获取选题**：模板/关键词 → 运行采集 → 多维挖掘 → 导出选题包  
2. **提取语料**：爆款「提取」→ 正文/OCR/ASR 入语料库 → 按维度检索  
3. **发布与追踪**：发布后贴链接 → 抓指标 → 关联选题与账号  
4. **复盘分析**：周/月对比内容类型、搜索词、账号表现 → 反哺下一轮选题  

---

## 5. Success Metrics

- **主指标：** 每周使用工具产生并导出的「选题包」数量  
- **副指标：** 语料库新增条数、追踪中自有内容数、复盘页周活  
- **质量指标：** 选题运行成功率（登录态有效占比）、追踪刷新失败率

## 6. Roadmap（Now / Next / Later）

### Now（轻量能力 · 已完成 / 加固）

- 小红书 / 视频号提取 + OCR/ASR  
- 能力式入口：爆款采集 / 选题分析 / 数据追踪可独立使用
- 采集深度 50/100/200，多轮排序扩大候选覆盖
- 采集阈值与结果二次筛选、排序
- 内容情报：选题独立爆款（折叠+分页）、转赞评播搜藏  
- 选题挖掘九维 + 场景矩阵 + 选题包导出  
- 自有内容追踪 + 趋势图修复  
- 本地一键启动 + GitHub 保护推送  
- 文档：README / DEPLOYMENT / INTEL 接入草案  

### Next（能力增强 · 按价值逐项启用）

| Epic | 假设 | 主要产出 |
|------|------|----------|
| E1 语料库 | 若爆款正文可检索+导出，生产侧改稿时间会下降 | `corpus_items` 表、提取→语料入库、筛选/导出 |
| E2 搜索展开词入库 | 若记录平台搜索联想/相关词，选题更贴搜索意图 | 抓取/粘贴入库、附在选题挖掘与榜单文案 |
| E3 轻量目标看板 | 若目标可选配置，负责人能看进度且不增加普通用户负担 | 可跳过的目标卡 + 周期复盘 |
| E4 追踪加固 | 若追踪与选题绑定，归因才成立 | tracked_posts 关联 topic / account；错误可自愈提示 |
| E5 同事上手包 | 若 README + 检测脚本齐全，同事可自装 | 依赖检测、redbook-skills 引导、demo 数据 |

### Later（平台化）

- 与物料生产平台发布回调对接（`external_*` 已预留）  
- 服务间 Token 严格鉴权 + 租户隔离  
- 账号矩阵画像（新号/成熟号）驱动选题强度  
- Postgres / 队列（数据量上来后）  
- 自动赛马标题/语料推荐（需更多样本）

## 7. Out of Scope（明确不做）

- 不做多账号营销托管 / 自动违规刷量  
- 不做「一键替所有同事远程登录小红书」（每人本地登录态）  
- 现阶段不做完整 SaaS 计费与多租户复杂权限  
- 不强制用户按固定市场工作流操作
- 不要求使用任何能力前先创建项目

---

## 8. Dependencies & Risks

| 风险 | 缓解 |
|------|------|
| 小红书 CDP / 登录墙 / 频率限制 | 状态灯、失败原因显性化、多轮间隔采集 |
| 搜索框展开词难自动化 | 先支持「截图/粘贴批量录入」+ 相关搜索词兜底 |
| 同事环境不一致 | 标准化 README、环境检测脚本、可选 Docker |
